# Regenerate API Reference Docs

The API reference is generated by TypeDoc and committed under `guide/api/{lib}/`.
Always process these modules together:

- `autk-core`
- `autk-db`
- `autk-map`
- `autk-plot`
- `autk-compute`

## For an Autark release

Prefer the repository automation, which checks out the exact coordinated package tag,
generates all references, excludes TypeDoc media, normalizes links, and updates the
site dependency:

```bash
npm run release:prepare -- --version <version>
```

Use `--dry-run` first when only validating the tag and collecting the source-impact
report is desired:

```bash
npm run release:prepare -- --version <version> --dry-run
```

The script writes a local review report to `.release/`; it is intentionally ignored
and must not be committed.

## Manual fallback

When a local Autark checkout is explicitly required, generate the docs from the
release checkout, never from an unpinned branch:

```bash
(cd "$AUTARK_PATH/autk-core" && npm run build)
for lib in autk-core autk-db autk-map autk-plot autk-compute; do
  (cd "$AUTARK_PATH/$lib" && npm run doc -- --skipErrorChecking)
done
```

Copy each `docs/` folder to its matching `guide/api/` destination, excluding
`_media/`. Replace the generated `README.md` with this `index.md` content:

```md
See [All Exports](globals.md) for the full API listing.
```

Update generated Markdown links from `README.md` to `index.md`.

## Required review and validation

1. Compare the generated API files with `git diff` and update the API sidebar in
   `guide/.vitepress/config.ts` for added or removed pages.
2. Search generated Markdown for unescaped generic syntax that VitePress could parse
   as HTML; quote any affected expressions with backticks.
3. Run `npm run build`. The production build must complete without errors.
